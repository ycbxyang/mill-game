# 棋类合集项目指导

## 项目定位

本项目将从单独的“磨坊棋”网页，逐步扩展为适合电脑、苹果平板和安卓平板使用的轻量棋类合集。

当前稳定版本为 **磨坊棋 v1.0.0**。它继续作为可独立使用的正式版保留。
棋类合集开发阶段使用 `v2.0.0-alpha` 版本号，全部核心功能稳定后再发布 `v2.0.0` 正式版。

## 当前开发状态

`v2.0.0-alpha.1` 已经建立游戏大厅，并完成三款游戏的第一版模块：

- 磨坊棋已迁移到独立目录，原有规则、AI 和联机功能保留。
- 四子棋已完成本地双人、三档 AI、远程房间、胜负和平局判断。
- 黑白棋已完成本地双人、三档 AI、远程房间、八方向翻转、自动跳过和终局计分。
- Firebase 改为仅在选择远程联机时加载，本地和人机模式不依赖网络。
- 房间会校验游戏类型和规则版本，避免不同游戏错误加入。

当前仍属于测试版本。发布前需要完成 GitHub Pages 上传及三款游戏的双设备联机实测。

## 第一批游戏

### 1. 磨坊棋

- 当前已经完成。
- 支持本地双人、人机对战和远程联机。
- 后续将现有规则、棋盘和 AI 移入独立游戏模块，玩法保持不变。

### 2. 四子棋

- 使用 7 列 × 6 行棋盘。
- 玩家轮流选择一列投入棋子。
- 棋子自动落到该列最下面的空位，不能悬空放置。
- 最先横向、纵向或斜向连成四枚棋子的一方获胜。
- 棋盘填满且无人四连时为平局。

计划支持：

- 本地双人
- 不同难度的人机对战
- 6 位房间码远程联机
- 重新开始和平局判断
- 手机及平板触控操作

### 3. 黑白棋

- 使用 8 × 8 棋盘。
- 初始时棋盘中央放置两枚黑棋和两枚白棋。
- 玩家落子时，必须从横向、纵向或斜向夹住至少一枚对方棋子。
- 被夹住的对方棋子全部翻转为当前玩家的颜色。
- 没有合法落子的一方自动跳过回合。
- 双方都无法落子或棋盘填满时结束，棋子较多的一方获胜。

计划支持：

- 合法落子位置提示
- 自动翻转棋子
- 本地双人
- 不同难度的人机对战
- 6 位房间码远程联机
- 无棋可下时自动跳过
- 终局计分

## 技术原则

### 游戏相互独立

每款游戏独立保存自己的规则、棋盘显示、AI 和测试。新增游戏时，不应修改其他游戏的核心规则。

### 通用功能只实现一次

游戏大厅、对战模式选择、Firebase 登录、房间创建、房间加入和断线提示由公共模块负责。

### 联机房间记录游戏类型

每个远程房间至少包含：

```js
{
  gameId: "connect-four",
  rulesVersion: 1,
  state: {},
  moveNumber: 0
}
```

双方只有在游戏类型和规则版本一致时才能开始，防止不同游戏或不同版本错误同步。

### 优先适配触控设备

- 主要按钮触控区域不小于约 44 像素。
- 横屏和竖屏都能完成对局。
- 不依赖鼠标悬停才能操作。
- 棋盘随屏幕缩放，但不能改变棋盘比例。

### AI 独立运行

每款游戏的 AI 使用独立 Web Worker，避免思考时卡住页面。所有难度都必须设置思考时间上限和应急落子。

## 开发路线

### 阶段一：搭建合集框架

1. 保留磨坊棋 v1.0.0 作为稳定备份。
2. 建立游戏大厅。
3. 将磨坊棋拆分为独立游戏模块。
4. 建立统一的游戏接口和联机状态格式。
5. 确认拆分后磨坊棋功能与 v1.0.0 一致。

### 阶段二：加入四子棋

1. 完成规则和棋盘。
2. 加入本地双人。
3. 完成人机 AI。
4. 接入远程联机。
5. 完成移动端和规则测试。

### 阶段三：加入黑白棋

1. 完成合法落子和翻转规则。
2. 处理自动跳过回合和终局计分。
3. 完成人机 AI。
4. 接入远程联机。
5. 完成移动端和规则测试。

### 阶段四：发布正式合集

1. 统一视觉风格。
2. 完成三款游戏的双设备联机测试。
3. 检查断线、刷新、重新开始和平局流程。
4. 发布棋类合集 v2.0.0。

## 每款游戏的完成标准

只有同时满足以下条件，游戏才能标记为“已完成”：

- 规则与胜负判断测试通过。
- 本地双人可以完成完整对局。
- AI 不会无限思考或下出非法棋。
- 两台设备可以完成远程对局。
- 重新开始后双方状态一致。
- 苹果和安卓平板均可正常操作。
- 不影响合集中的其他游戏。

## 暂不纳入第一批

中国象棋、国际象棋和围棋的规则、AI 与联机验证明显更复杂，暂不纳入第一批开发。待三款核心游戏稳定后，再决定下一批游戏。
